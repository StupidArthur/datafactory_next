## 一、发明概述与信息确认

### 1.1 一句话概述

本技术提出一种面向工业算法测试的实时仿真闭环交互机制：将外部工业通信写请求按其目标仿真实例分别验证和提交，由实例独立的周期调度器在模型计算边界应用写入；在单实例写入失败时维持该实例计划周期的模型推进，并将成功写入的实际生效周期与模型快照关联，以减少跨实例写入相互干扰、写入生效时序不明确以及发布数据与模型状态脱节的问题。

## 二、技术领域与背景技术

### 2.1 技术领域

本发明属于计算机实现的工业过程仿真与测试技术领域，具体涉及离散周期模型的执行控制、独立仿真实例管理、经工业通信接口接收外部输入的周期边界提交、模型状态快照发布以及写入生效状态的关联记录。相关技术可应用于工业算法仿真测试、控制策略验证环境及自动化系统的隔离测试。

### 2.2 背景技术及既有方案

工业算法测试通常需要模拟过程测量值、执行器反馈和受控对象的动态变化。现有技术中，已有模拟工业过程并按实时或加速时间运行的方法，也有通过 OPC UA 连接仿真模块、协调仿真步长的技术，以及将 OPC UA 写操作暂存后延迟处理的方案。这些通用能力本身不作为本技术的独有发明点。
在一台服务主机中并行运行多份独立模型、同时对外提供同一个工业通信端点时，外部请求可能一次包含多个实例的变量，且请求到达时间不必与任一模型周期一致。如采用不区分实例的整体拒绝规则，可能因为某实例的非法输入影响其他实例；如直接修改对外通信节点而非模型状态，则后续模型演算可能与外部读值不一致；如将异常写入等同于放弃整个模型周期，则过程仿真时间和连续动态可能产生非预期缺口。

## 三、拟解决的技术问题

针对上述应用环境，本发明拟解决的具体技术问题包括：
同一外部工业写请求包含不同仿真实例的写入项时，如何对各实例的合法输入独立处理，并使某实例的错误不引起另一实例的合法批次被误拒绝。
外部请求与模型周期异步到达时，如何以明确的模型执行时点应用外部输入，避免外部通信节点成为脱离 Engine 的第二份模型状态。
整批写入校验失败时，如何保持该实例按既定调度继续推进当前周期，同时避免非法批次产生部分状态变更。
如何为成功写入记录其实际影响模型计算的周期编号，并使对外发布变量可关联于一次模型执行后的快照。
本发明不试图解决跨实例分布式事务、跨实例强制同步、真实生产安全联锁或被测算法正确性自动判定等问题。

## 四、发明技术方案（核心）

### 4.1 总体结构

系统由组态编译单元、统一模型执行引擎、实例管理器、每实例实时调度器、写入队列与状态登记单元、工业通信适配器、快照发布单元组成。组态编译单元根据声明式模型建立编译工件及变量目录；实例管理器可为一份或多份组态启动多个独立 Engine。Fast 宿主无需真实时间等待即可连续调用同一 Engine；Realtime 宿主按实例周期调度 Engine，并通过工业通信服务端与外部被测算法交互。

**图1  双运行宿主与统一模型执行核心的逻辑结构**

### 4.2 模型工件与变量元数据建立（步骤 S101—S102）

S101：读取包含模型周期 Δt、变量定义、组件参数和组件连接关系的 DSL 组态，编译为统一 Engine 可装载的模型工件。模型工件包含变量目录（名称、数据类型、初值、读写属性等）以及组件执行所需的节点信息。
S102：按照 Host 配置创建实例集合 I={I₁,I₂,…,Iₙ}。每一实例 Iᵢ 至少独立保存模型状态 Xᵢ、仿真周期编号 kᵢ、周期时长 Δtᵢ、待写队列 Qᵢ、写入状态登记 Rᵢ 及最近快照 Sᵢ。实例之间不默认共享组件状态或写入队列。

### 4.3 外部请求验证与按实例拆分（步骤 S103—S104）

S103：工业通信服务端接收外部写请求 W={w₁,…,wₘ}。各写入项携带目标节点、属性、索引范围和数值；适配器识别客户端访问角色，并结合变量目录校验 NodeId 是否为已知 Tag、Tag 是否可写、值的类型是否匹配、请求属性与索引范围是否有效。
S104：对能够关联实例 Iᵢ 的写入项，根据校验结果形成有效写入集合 Vᵢ 及实例拒绝标识 Eᵢ。若请求中某项可明确归属 Iᵢ 且校验失败，则不将该请求内 Iᵢ 的其他有效项提交，返回相应逐项状态；对于不同实例 Iⱼ，只要其对应请求项合法，仍能独立形成批次 Bⱼ 并尝试入队。对无法识别目标实例的未知节点，只返回该节点错误，不据此全局否决所有实例。

**图2  同一 OPC UA 请求按实例分组、校验、隔离与提交的流程**

### 4.4 独立队列与模型周期提交（步骤 S105—S106）

S105：每个实例采用有界 FIFO 队列存放已接纳的实例级写入批次；达到容量上限时立即拒绝新批次，已入队批次保持原有顺序。实时调度器到达本实例计划周期边界时，至多取出一个批次；没有待处理批次时使用空写入集合调用 Engine。
S106：Engine 先对该批次中的变量存在性、写权限及值类型进行整批校验，通过后再将写入值作为当前单周期计算的输入并推进一次模型状态。成功时产生新快照，周期编号增加 1。若 Engine 判定批次为外部写入拒绝，且此前未使模型状态发生部分提交，则该实例丢弃此批值，在同一计划周期以空写入重新执行一次 Engine 单周期，使该计划周期仍可完成。若计算引擎发生与外部写入不同的致命错误，则进入实例故障状态，不能错误地宣称总能继续运行。

**图3  实例级写入在模型周期边界的应用、拒绝与持续推进**

### 4.5 回执、写入生命周期与快照发布（步骤 S107—S109）

S107：当 Engine 接受并完成一个包含外部写入的周期后，写入登记单元为该批次保存实际生效周期 effective_cycle_index 与 simulation_time。模型以 t=k×Δt 推进仿真时间；回执记录的是模型实际生效时点，而非网络请求到达的墙上时间。内部状态可区分“排队、应用中、已生效、已拒绝、已取消”，并允许按请求编号查询。
S108：快照发布单元从同一实例 Engine 最近完成的状态快照中提取 Tag 值，并与该实例运行状态一并构造成批量节点更新，通过工业通信服务器写入本实例节点，再由订阅机制向客户端发布。该实例的一次批量发布取自同一模型快照；不同实例无需具有相同的周期编号。
S109：当客户端等待写入回执发生超时，后台批次可能仍处于排队、应用或已生效状态；超时只代表响应等待期限届满，不自动取消请求。现有实现对写入状态的查询在 Runtime 内部，不能描述为已经通过标准 OPC UA 服务公开查询 API。

## 六、具体实施方式

### 6.1 实施例一：双实例水箱仿真与故障隔离

如图1和图2，Host 配置启动实例 A 和实例 B，分别加载二级圆柱水箱 DSL 工程。工程含入口流量变量 plant_inlet_flow（初值 0.0012 m³/s，writable=true）及 tank_1、tank_2 模型，其中 tank_1 的出口连接 tank_2 入口。工程周期 Δt=0.5 s；每实例有独立 Engine、队列、仿真时间、状态快照。
外部 OPC UA Client 通过同一服务端发送包含多个实例 Tag 的 Write 请求。示例中，A 的写入批次包含一项可归属于 A 的非法变量写入，而 B 的写入项合法。适配器先逐项校验，再按实例分组；A 的同请求合法项因 A 批次被否决而不提交，B 批次独立进入 B 队列，随后在 B 的某周期边界生效。读取两个实例的水箱液位及周期值，验证对 A 的异常写入不会强制取消 B 的合法提交。
进一步采用单实例的非法输入场景，验证 Engine 拒绝写入后该实例仍以空写入完成当次周期，而非法写入前模型状态不发生部分更新。该实施例说明实例级失败隔离和周期连续性，不能据此推导跨实例统一时间屏障或物理设备控制性能。

### 6.2 实施例二：外部 PID 设定值驱动双水箱实时闭环

采用 examples/two-tank/pid-closed-loop.yaml。周期 Δt=0.5 s；source_flow 初值为 0.0012 m³/s；可写 Tag level_setpoint 初值约 0.09706422 m。PID 模型 pid2 以 tank_2.level 为 PV、level_setpoint 为 SV，输出 MV；VALVE 模型以 MV 为目标开度、source_flow 为入口流量，输出流量流入 tank_1，tank_1 出口再流入 tank_2。除 level_setpoint 外，PID 和水箱过程输出保持只读。

**图4  外部设定值、PID、调节阀与串联双水箱构成的闭环模型**

测试时，由真实 OPC UA 客户端写入 level_setpoint，Runtime 在可确定的模型周期施加设定值，之后继续按周期执行 PID、阀门及两个水箱模型；客户端读取 pid2.MV、valve_1.current_opening、valve_1.outlet_flow、tank_1.level 和 tank_2.level 等过程变量，可观察到随设定值变化而产生的动态响应。项目工程验证记录了设定值变化后 MV、阀门开度、出口流量与液位的变化。该实施例用于证明“外部写入→模型计算→动态过程输出→反馈”闭环，并非预存数据回放；不据此宣称 PID 已完成工业整定、稳定性证明或达到指定稳态误差。

### 6.3 实施例三：快速仿真和实时仿真的计算语义一致性

使用同一 DSL 组态分别创建快速宿主和实时宿主的独立 Engine。快速宿主不等待真实时间，连续调用 Engine.execute；实时宿主按墙上时间触发单周期执行。比较时，根据实时写入成功回执中的 effective_cycle_index 将同样的输入放置于快速宿主的对应模型周期，再检查周期序号、simulation_time 与各 Tag 的类型和数值是否满足既定精度容差。
这一过程是验证共享计算语义的测试实施方式。它不要求两个宿主墙上时间同步，也不意味着现有产品已经提供面向普通用户的自动录制/重放功能。

## 八、建议保护的关键技术特征与可替代实施方式

### 8.1 首选保护组合

在同一外部工业通信请求内，逐项识别与校验目标节点，并根据目标模型实例进行批次划分；仅对可归属实例的错误建立实例级否决，而非全局失败扩散。
各实例独立保存仿真模型状态、调度周期、有限容量的写入 FIFO 队列；在各自周期边界提交并整批校验。
当整批写值被 Engine 拒绝时，维持该实例当前计划模型周期执行，避免将外部非法写入误当作模型计算周期取消。
在成功应用时生成与模型周期相关的生效回执，并使用模型本周期快照完成一次实例范围的变量发布。

### 8.2 可从属保护或备用技术特征

写入请求状态机及在排队阶段可取消、应用阶段不可取消的分界。
外部等待超时不自动撤销已排队写入，以及内部追踪其后续终态。
从 Tag Catalog 自动构建实例路径、NodeId、权限与工程单位；OPC UA 作为一个具体工业协议实施方式。
快速宿主与实时宿主复用相同编译工件及 Engine，通过周期输入定位可对照计算状态。

### 8.3 允许的等效实现

在不改变核心逻辑的前提下，声明式组态可采用其他结构化表达形式；工业通信适配器可替换为能够表达目标实例和变量写入的其他协议；同一实例的队列数据结构可采用其他具备顺序和容量约束的实现；状态快照可采用不可变视图或同步复制结构。此类等效设计仅为代理人判断保护范围的可选实现，不表示仓库当前已全部支持。
