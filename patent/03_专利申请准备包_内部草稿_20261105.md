## 4. 技术交底重写稿（核心方案）

### 4.1 技术领域与背景

涉及工业算法测试、离散周期仿真引擎、实时调度及 OPC UA 数据交互。现有工业仿真工具已支持加速/实时模式，也已支持 OPC UA 联合仿真和写入暂存；因此本文不将上述能力孤立视为区别点。

### 4.2 需要解决的问题

在一个 OPC UA 服务节点发布多个独立工业场景时，外部同一请求可能包含多个实例的 Tag 写值，个别 Tag 非法或运行时队列拥塞会使模型写入时点、异常传播与外部观测不确定。需要在不引入跨实例全局事务的情况下，维持各实例计算状态、周期推进和写入结果的一致性。

### 4.3 完整执行流程

- S101 解析 DSL v2 并构建编译工程和 Tag Catalog，建立包含实例 ID、变量类型、可写属性及节点 ID 的映射。
- S102 为 Host 中每个启用的组态创建独立 Engine、仿真周期计数器、墙上时钟调度器、有限容量的 FIFO 写入队列与状态快照。
- S103 OPC UA Server 接收 Write 请求并识别客户端身份，逐项验证 NodeId、写值类型、访问权限与可写性；对可归属实例的 Tag 形成实例级拒绝信息。
- S104 将验证通过的写值按实例 ID 分组。实例 A 含已归属的非法 Tag 时，不提交 A 的其余合法写值；实例 B 的合法批次独立进入 B 的队列。
- S105 各实例的调度器到达本实例某一计算周期边界后，至多取出一组待写值，交给统一 Engine 进行整批校验与该周期模型计算。
- S106 Engine 接受批次则推进一个周期并返回快照、生效周期号和仿真时间；Engine 拒绝外部输入时，该实例执行不携带该批写值的同一计划周期并更新拒绝记录。
- S107 发布器基于该实例最新 Engine 快照及运行状态，构造 Tag、状态节点的批量 OPC UA 更新，并通过订阅推送给客户端。
- S108 对客户端超时但后台仍可能生效的写入，保留内部写状态；不将超时直接转换为取消，并不宣称现已提供 OPC UA 写状态查询服务。
### 4.4 关键异常与边界

- 无已连接 Runtime 或实例停止：合法节点的写入返回不可服务，不进入已经停止的模型。
- 队列已满：立即拒绝新的整个实例写批次；不丢弃队列中已接纳批次。
- 输入包含不可归属实例的未知 NodeId：返回该节点异常状态，不能无依据地否决所有实例。
- 跨实例：每个实例独立提交，系统不提供跨实例原子事务或统一时钟推进屏障。
- 客户端收到 OPC UA 写超时：实际是否生效存在不确定性，不能直接推断取消。
- 快照发布：保证单实例发布批次的模型周期来源一致，不宣称跨实例快照时间戳完全同步。
### 4.5 可复现实施例

实施例一：双实例水箱。A/B 加载相同模型但具有不同独立 Engine；Write 请求中 A 含非法 Tag、B 为合法输入，预期 A 的相关合法写项不提交、B 可在本实例周期执行。保存请求状态、模型周期与 A/B 位号变更对照。

实施例二：PID 水箱。外部客户端写 level_setpoint，写入流向 PID 输入、阀门目标/实际开度、两个水箱液位的周期状态，形成真实运行时闭环。现有断言证明动态响应，并不能延伸为稳态收敛或设备级安全。

实施例三：Fast/Realtime 周期对照。采用相同 DSL、相同初始条件与输入值，按 Realtime 写回执中的 effective_cycle_index 在 Fast Engine 中重放；比较全部 Tag 类型与数值容差。此为当前测试证明方法，不应表述为已交付可操作回放产品。

## 5. 候选权利要求（代理人审核稿）

以下候选条款优先选择代码可实施且验证路径清楚的限定；未评估满足全部授权要求。正式代理撰写时应校正单一性、支持性、清楚性及最佳保护范围。

### 权利要求 1｜方法独立项（保守范围）

一种面向工业算法测试的多实例仿真数据闭环交互方法，由包含工业通信服务端和多个模型运行实例的计算机系统执行，其特征在于：

（1）基于至少一份声明式模型组态获得仿真模型工件及变量目录，并为多个仿真实例分别创建具有独立模型状态、仿真周期计数器和外部写入队列的模型执行环境；

（2）通过 OPC UA 服务端接收包含多个变量写入项的写请求，根据变量目录确定各写入项所关联的仿真实例并对各项执行节点映射、类型和可写性校验；

（3）将可接受的写入项按其目标仿真实例组织为实例级写入批次；当写请求中存在能够映射到某一实例的非法写入项时，阻止该实例的同一请求批次提交，同时允许所述写请求中其他实例的合法写入批次分别提交；

（4）由每一仿真实例在其自身调度周期边界从相应写入队列获取写入批次，调用该实例的模型执行引擎整批校验并执行该周期模型计算；在所述模型执行引擎拒绝整批写入的情况下，仍使用不包含该批写入值的输入推进该实例的当前计划模型周期；

（5）对被执行引擎接受的写入批次记录对应的实际生效周期编号及仿真时间，并基于该实例本周期生成的模型状态快照向 OPC UA 节点发布变量值。

### 权利要求 2–7｜从属项（候选）

- 权2：每个实例的写入队列为有限容量 FIFO 队列，容量满时拒绝新批次而保持已接纳批次。
- 权3：每个实例的一个模型周期最多从队列取出一个写入批次。
- 权4：维护写入请求标识与排队、应用中、已生效、已拒绝和已取消的状态，并对已生效批次关联周期号。
- 权5：在 OPC UA 请求等待超时但后端批次仍排队或应用中的情况下，不将该超时作为该批次已取消的证明。
- 权6：使用每个实例的变量目录构建独立的 OPC UA 节点标识，并按一个实例快照批量更新该实例的 Tag 和状态节点。
- 权7：快速仿真宿主与实时宿主均调用同一模型执行引擎的周期计算接口，前者不等待墙上时钟，后者按墙上时间调度。
### 权利要求 8–9｜系统与存储介质（候选）

权8：一种实现权利要求1–7任一方法的系统，包括组态编译模块、多个模型执行实例、各实例独立调度与写入队列、OPC UA 适配层、写入状态记录模块及快照发布模块。

权9：一种计算机可读存储介质，其上存储的指令由处理器执行时实施权利要求1–7任一方法。

### 保留两个可选申请主题

备选 A：周期级写入生效与可复现实验方法。风险：如果只存在测试代码，应避免将其定义为已交付独立产品功能。备选 B：实例级 OPC UA 批次隔离与恢复语义。建议首案先集中于“异常写入不丢周期 + 实例级隔离 + 生效周期回执”的结合，并根据进一步检索决定是否分案。
