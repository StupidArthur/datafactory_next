# DataFactory 技术交底草稿（非公开工作底稿）

**状态：技术交底初稿；尚未完成现有技术检索、权利要求定稿与专利代理审查。**  
**依据：** `datafactory_next` 的 Rust Engine、Runtime、OPC UA 代码及 R8/R9/PID 工程证据（截至 2026-11-05）。

## 一、发明主题（建议讨论名称）

**一种面向工业算法测试的双时间域仿真及多实例闭环数据供给方法、系统与存储介质。**

拟解决的技术问题：工业算法测试通常需要既能快速产生大规模时序样本，又能与外部算法按真实时间交互；当存在多个仿真实例及异步写入时，还需避免模型状态不一致、写入时序不确定、跨实例相互影响。

## 二、总体技术方案

采用同一份声明式工业模型定义（DSL v2），经编译器生成统一模型工件；统一 Engine 持有变量、组件内部状态、组件依赖与计算顺序。两个宿主调用同一个执行核心：

1. **快速仿真宿主**：连续执行模型周期，不受真实时间节拍限制，按采样策略生成趋势与离线数据；
2. **实时仿真宿主**：以墙上时间驱动周期调度，通过独立实例的模型状态、写入队列及快照发布机制向外部系统供数；
3. **外部交互适配**：将模型 Tag 的类型与访问权限映射为 OPC UA 节点，接收写值请求并在对应实例的后续模型周期边界作用于 Engine；
4. **生效可追溯**：内部关联写入请求与周期生效序号，依照模型执行成功或失败返回回执与状态；
5. **多实例隔离**：一个 Host 管理多个独立的 Engine/调度器，OPC UA 同一个服务端中以实例化命名空间发布；单实例的写入校验失败不连带其他实例批次。

**重要区别：实时模式直接计算动态模型，不是预生成数据的网络回放。**

## 四、实施例

**实施例 A：离线/实时一致性。** 同一工程、相同初始状态与外部输入序列，在 Fast Engine 上按 Runtime 写入回执记录的 `effective_cycle_index` 重放，逐周期比较变量类型与数值（给定容差）。须待本轮测试 CI 通过后才能宣称取得对应验收证据。

**实施例 B：双实例隔离。** 一台 Runtime Host 管理水箱 A/B，独立 OPC UA 客户端会话分别对两个实例进行读写；实例 A 合法输入推动水箱 A 液位改变，而实例 B 保持自身独立演进。写入批次跨实例拆分，不宣称跨实例事务原子性。

**实施例 C：PID 设定值闭环。** OPC UA Client 写入液位设定值，Runtime 在生效周期施加到 PID，PID 调整阀门开度及流量，两个水箱液位发生动态响应。现有工程证明控制链路响应，**不能**表述为完成 PID 收敛、实物整定或安全控制。

## 九、候选权利要求结构（供专利代理人重构）

> 下述仅为技术性表述草案，**不是已确认具备新颖性的权利要求**。独立权利要求范围应在完整对比 ABB、Emerson、Siemens 及其同族、引用文献后确定。

**候选独立方法项：**

一种面向工业算法测试的仿真数据供给方法，应用于包括模型编译单元、统一执行引擎、实时调度单元及工业通信适配单元的计算系统，其特征在于：

（a）解析含组件定义、变量及周期参数的声明式模型组态，编译形成可由统一执行引擎加载的模型工件和变量目录；

（b）根据实例配置分别建立多个模型运行实例，各实例独立维护组件内部状态、仿真时间、运行周期编号以及有界外部写入队列；

（c）使实时调度单元依据墙上时钟驱动对应实例逐周期执行模型，其中单次成功执行按模型周期推进仿真时间；

（d）工业通信适配单元依据变量目录将外部写入按目标实例分组，对每一实例的写入批次校验变量存在性、可写性和数据类型，并将通过校验的批次提交到该实例队列；

（e）在实例的指定周期边界处理写入批次，经统一执行引擎进行批次原子校验并应用于该周期计算，记录写入请求的生效周期编号；当该批次被拒绝时，该实例继续执行不携带该批写入的当前模型周期；

（f）由统一执行引擎生成周期状态快照，工业通信适配单元依据所述快照更新对外发布变量，而不将对外节点缓存作为独立的模型状态；对不同运行实例分别记录写入结果，避免一个实例的拒绝导致其他实例的合法批次被整体回滚。

**候选从属项分组：**

1. 统一 Engine 还能由快速仿真宿主在不等待墙上时钟的情况下连续推进，并通过按周期编号重放相同输入形成可比较的仿真快照；
2. 每实例在周期内最多取出一个 FIFO 写入批次，队列容量超限时拒绝新批次，同时保留已入队批次；
3. 将写入请求生命周期区分为已排队、正在应用、已生效、已拒绝和已取消等状态，并记录应用后的生效周期与仿真时间；
4. OPC UA NodeId 按实例 ID 与 Tag 标识构建，实现实例状态、工程单位及变量类型/权限的隔离映射；
5. 在外部写入超时后不将超时直接解释为写入撤销，仍通过后台状态记录追溯后续生效；
6. 各实例支持独立的延迟或追赶调度策略，并分别记录运行周期、超时次数与计算耗时。

**候选装置/介质项：** 基于上述方法，构建包含模型编译模块、统一执行引擎模块、实例调度和管理模块、写入事务管理模块、工业协议发布模块的系统，以及存储有执行上述方法指令的计算机可读存储介质。

**特别需要代理人重点质询：** 上述独立项中的“双宿主”“闭环通讯”要素与公开技术已高度重合，可能需要进一步收窄；实例级失败隔离、周期边界确认、空写周期等机制需要明确相对最接近技术的区别和非显而易见的技术效果。不要用代码实现数量或 CI 通过率替代专利创造性论证。
